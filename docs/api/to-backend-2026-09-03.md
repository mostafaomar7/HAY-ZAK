# مشّينا دورة الدفع كاملة على السيرفر الجديد — شغّالة، وفاضل حاجة واحدة

جرّبنا كل خطوة النهارده على `https://179-198-199-243.sslip.io/api/v1` بعد
الـreset. كل سطر تحت من نداء فعلي.

## اللي اشتغل — الدورة كلها

| الخطوة                          | النتيجة                                                                   |
| ------------------------------- | ------------------------------------------------------------------------- |
| `POST /renter/bookings`         | `201` · `AWAITING_PAYMENT` · مهلة ١٥ دقيقة                                |
| `POST /renter/bookings/:id/pay` | `200` · `redirectUrl` **مش `localhost`**                                  |
| صفحة الدفع                      | فتحت، وفيها «ادفع الآن» و«ارفض البطاقة»                                   |
| «ادفع الآن»                     | `303` → الحجز بقى `CONFIRMED`                                             |
| الفواتير                        | `INV-2026-000001` BOOKING للمستأجر · `INV-2026-000002` COMMISSION للمؤجّر |
| بيانات التواصل                  | اتفتحت بعد الدفع، و`null` قبله                                            |
| مستحقات المؤجّر                 | `pendingHalalas: 19125` = ٢٢٥٠٠ − ٣٣٧٥ ✔                                  |
| «ارفض البطاقة»                  | الحجز فضل `AWAITING_PAYMENT` بحجزه سليم، والتواصل فضل `null`              |
| النداء تاني بعد الرفض           | نفس العملية بالظبط، مش عملية جديدة ✔                                      |

**مسألة الـ`localhost` اللي كنا هنكلّمكم فيها اتحلّت خلاص** — الـ`redirectUrl`
طالع على العنوان العام. وكمان الصفحة بتحافظ على الـquery اللي بعتناه: بعتنا
`?bookingId=…` ورجع زي ما هو ومعاه `status` و`charge`. ده بالظبط اللي صفحة
الرجوع عندنا محتاجاه، لأنها بتقرأ الحجز من عندكم ومش بتصدّق `status`.

و`/uploads` متعمله proxy على نفس الأصل — رفعنا صورتين وفتحناهم `200 image/png`.

## الحاجة الوحيدة الفاضلة: صفحة الدفع بتتفتح على `http`

```
redirectUrl: http://179-198-199-243.sslip.io/api/v1/webhooks/payments/…
             ^^^^
```

الـ`form` جوه الصفحة نفسها بيبعت على `https` — يعني ناقصة الحرف ده في مكان
واحد بس، وهو الرد بتاع `/pay`.

مش بيوقّف الدورة، لأن الانتقال ده انتقال كامل للمتصفح مش طلب فرعي، فالمتصفح
بيسمح بيه. بس النتيجة إن **صفحة فيها مبلغ واسم عميل ورقم حجز بتتفتح على اتصال
مكشوف**، والمستخدم بيشوف «غير آمن» في شريط العنوان في نص أكتر لحظة بيبقى فيها
حسّاس. وساعتها بيبقى فيه انتقال https → http → https من غير سبب.

**المطلوب:** `redirectUrl` يتبني على `https` زي ما الـ`form` عامل بالظبط.

## داتا التجربة — إيه اللي سبناه ورانا

القاعدة كانت فاضية تمامًا بعد الـreset (صفر مساحة وصفر حجز)، فاضطرينا نعمل
اللي نجرّب بيه:

- **مساحة** `PROBE — مستودع اختبار الدفع (احذفه)` باسم المؤجّر خالد العتيبي —
  **أرشفناها**، فمش ظاهرة في الكتالوج (`/public/units` رجع صفر تاني).
- **حجز `HZ-2026-09-0001`** — `CONFIRMED`، وسايبينه لأن عليه فاتورتين وده اللي
  بيثبت إن الدورة تمّت.
- **حجز `HZ-2026-09-0002`** — اللي جرّبنا عليه الرفض، سايبينه ينتهي لوحده بعد
  المهلة.

لو حابين تمسحوهم مع أول reset جاي مفيش مانع — كلهم داتا اختبار.
