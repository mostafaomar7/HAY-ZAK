# بعد التيست — ٤ تناقضات وفجوة واحدة

جرّبنا كل اللي بعتّوه على `192.168.1.17:4000` النهارده.

**السلوك الأمني كله مظبوط** ومحتاجش مراجعة — الصلاحيات، الرفض، الأكواد،
الملاحظات الداخلية. الأشكال هي المشكلة.

كودنا كان غلط في ١٠ مواضع لأننا بنيناه على الوصف. مصلّح كله. اللي تحت هو
اللي محتاج منكم **قرار أو تأكيد**، مش أكتر.

---

## أولاً: أربع جمل في البرومبت بيكذّبها السيرفر

هدول الأربعة هم اللي كلّفونا وقت فعلي.

### ١. `isOverdue` — مش بيتبعت أصلاً

قلتوا:

> «وكل صف فيه `isOverdue: boolean` — اعرضها كـ badge أحمر.»

الحقل **مش موجود** في أي رد — لا في `/admin/complaints` ولا في التفاصيل.
الفلتر `?overdue=true` شغّال ٢٠٠، لكن القيمة نفسها مش بتترجع.

**اللي عملناه مؤقتًا:** بنشتقّه عندنا — `slaDueAt` عدّى و`firstResponseAt`
لسه `null`.

⚠️ ده حسابنا إحنا، مش حقيقة من عندكم. يعني ممكن الصف اللي بنلوّنه أحمر
مايظهرش في `?overdue=true` والعكس — رقمين لحقيقة واحدة.

**المطلوب:** ابعتوا الحقل. لو منطقكم مختلف عن اشتقاقنا، قولوا إيه هو.

### ٢. `refunds[]` — مش موجود

قلتوا:

> «`GET /admin/complaints/:id` فيه `refunds[]` — اللي اترد فعلاً على القضية دي.»

مفيش. مفاتيح رد التفاصيل بالظبط:

```
id, referenceNo, category, subject, description, status,
resolution, resolutionNote, resolvedAt, slaDueAt, firstResponseAt,
raisedByType, assignedToId, booking, messages, createdAt, updatedAt
```

**اللي عملناه:** شلنا القسم. المبلغ المسترد بيتقري من `resolution`.

**السؤال:** هل `refunds[]` جاي، ولا نعتمد على `resolution` نهائيًا؟

### ٣. `/public/settings` — ملفوف مش مباشر

قلتوا:

> «بيرجّع object مباشر بالقيم محوّلة: `{ "marketplace.page_size": 12 }`»

اللي بيرجع فعلاً:

```json
{ "settings": { "marketplace.page_size": 12, "booking.hold_minutes": 15 } }
```

القيم محوّلة صح ✅ — بس فيه غلاف `settings`.

### ٤. `multipart` مش إجباري

قلتوا (بعلامة تحذير مزدوجة):

> «⚠️⚠️ الاتنين بتوع الـ POST **multipart/form-data إجباري** — مش JSON.»

الـ JSON بيعدّي عادي في الاتنين. جربناه ورجع `201`.

مش مشكلة عندنا — إحنا بنبعت multipart دايمًا عشان يبقى مسار واحد. بس
التحذير ده كان هيخلّي حد يدوّر على باج مش موجود.

## ثانيًا: فجوة حقيقية

### `/admin/reference` مبيرجّعش الأحياء

الرد فيه `categories` و`cities` و`prohibitedItems` **وبس**.

بس مساراتها موجودة وشغّالة:

```
POST /admin/reference/districts
PUT  /admin/reference/districts/:districtId
```

يعني نقدر نضيف ونعدّل حي، ومش قادرين نعرضه.

**اللي عملناه:** الشاشة بتقول «لا يرجع السيرفر قائمة الأحياء بعد» — مش
«لا توجد أحياء»، لأن الاتنين مش نفس الكلام.

### `/renter/bookings` و`/lessor/bookings` مفيهمش صورة للمساحة

`booking.unit` فيه `id` و`title` و`addressLine` و`city` **وبس**.

يعني شاشة «حجوزاتي» مبتعرفش تعرض صورة المساحة اللي المستخدم حاجزها — بتحط
مكانها المربع المخطط. `/public/units` بيبعت `coverUrl` عادي، فالحقل موجود
عندكم على المساحة نفسها.

**المطلوب:** `unit.coverUrl` في الاتنين، زي ما هو بالظبط في `/public/units`.

⚠️ ملاحظة منفصلة: **مفيش ولا مساحة واحدة على السيرفر عندها صورة** — كل
٢١٨ إعلان `coverUrl: null` و`imageCount: null`. ده مش باج عندنا ولا عندكم،
بس معناه إن أي حد بيراجع الواجهة النهارده شايف مربعات مخططة بس. لو تقدروا
تحطوا صور على كام إعلان في الـ seed هيبقى أوضح للي بيستعرض.

## ثالثًا: أشكال شغّالة بس مش موصوفة

مش أخطاء — بس كل واحدة فيهم كلّفتنا دورة تصحيح. اكتبوها في التسليم الجاي.

### الرد على إرسال رسالة

**ده كان أخطر واحد.** `POST .../messages` بيرجّع:

```json
{ "message": { "id", "senderType", "body", "isInternal", "attachments", "createdAt" } }
```

إحنا كنّا بنقرا `response.complaint` — يعني **أول رد يكتبه أي مستخدم كان
هيرمي exception**، على شاشته وعلى شاشة الإدارة.

مصلّح: بنعيد قراءة الشكوى بعد الإرسال — وده لازم برضه، لأن الحالة اللي
الرد بيحرّكها (`AWAITING_USER` → `IN_PROGRESS`) متبانش غير بقراية تانية.

✅ **اقتراح:** رجّعوا `{ complaint }` من `resolve` و`close` **و`messages`**
كمان. الاتنين الأولانيين بيعملوا كده فعلاً، والتالت هو الشاذ.

### الرسالة فيها `senderType` مش اسم

```json
{ "senderType": "RENTER" | "LESSOR" | "ADMIN", "createdAt": "..." }
```

مفيش `authorName` ولا `sentAt`.

✅ **وده صح**، ومش بنطلب تغييره: المستأجر مالوش يشوف مين الموظف اللي رد،
واسم المؤجّر مش حقه (SRS §5). بنعرض «الدعم / المستأجر / المؤجّر».

⚠️ بس الأدمن كمان مش شايف مين من زمايله رد. لو ده مقصود تمام؛ لو لأ،
`senderName` للأدمن بس هيكون مفيد.

### باقي الاختلافات

| المكان                 | الوصف قال              | السيرفر بيبعت                                                |
| ---------------------- | ---------------------- | ------------------------------------------------------------ |
| الشكوى                 | `booking.unitTitle`    | `booking.unit.title` متداخل                                  |
| الشكوى                 | المرفقات على الشكوى    | المرفقات على **الرسايل** — حتى بتوع الفتح                    |
| الشكوى                 | `assignedToName`       | `assignedToId` بس، من غير اسم                                |
| المرفق                 | —                      | `url` نسبي `/uploads/...` — محتاج أصل الـ API                |
| سجل التدقيق            | `oldValue`, `newValue` | **objects** مش نصوص                                          |
| `/admin/audit/actions` | «قائمة الفلتر»         | `[{ action, entityType }]` مش نصوص                           |
| `/admin/settings`      | —                      | ملفوف في `items`                                             |
| `dataType`             | —                      | `INTEGER` / `STRING` / `BOOLEAN` بحروف كبيرة                 |
| `/admin/cms/pages`     | —                      | ملفوف في `items`                                             |
| `/public/pages`        | —                      | ملفوف في `items`                                             |
| المستخدم               | `verificationProvider` | متداخل جوّه `identity`                                       |
| تقرير الحجوزات         | —                      | `bookingsCount` مش `count`                                   |
| تقرير المؤجّرين        | —                      | `{ lessor: {id, fullName}, units, bookings, earnedHalalas }` |

⚠️ **`oldValue`/`newValue` تحديدًا:** `{{ oldValue }}` على object بيطبع
`[object Object]`. لو حد بنى شاشة سجل تدقيق من غير ما يفتح الرد، هيشحن ده.

### الـ overview جزئي مش كامل

قلتوا:

> «✅ كل بلوك في overview فيه **كل** المفاتيح بأصفار. متحطش `?? 0` على أي حاجة.»

`byRole` مفيهاش `GUEST` خالص، و`byStatus` فيها `DELETED` اللي مش في وصفكم.
و`byStatus` بتاعة تقرير الحجوزات بترجع الحالتين الموجودتين بس.

مش مشكلة — بنمشي على اللي بيتبعت. بس النصيحة «متحطش `?? 0`» بتفترض
اكتمال مش موجود.

## رابعًا: إعدادان ناقصان

مفيش مفتاح لأي من دول:

- **مهلة مراجعة الإعلان** — تلات شاشات بتلوّن الصف «متأخر» على أساسها
- **دورة صرف المستحقات** — مكتوبة في ترويسة شاشة التحويلات

الاتنين شغّالين على قيم مكتوبة جوّه الكود. لو هما ثابتين خلاص قولوا وهنسيبهم؛
لو المفروض الأدمن يغيّرهم، محتاجين `operations.approval_sla_hours` و
`payout.cycle_hours` في `/admin/settings`.

## خامسًا: اللي اتأكد إنه شغّال ١٠٠٪

عشان متراجعوش حاجة من دول:

```
FINANCE    → GET  /admin/complaints          403 ✅
OPERATIONS → GET  /admin/complaints          200 ✅
OPERATIONS → resolve { REFUND }              403 ✅
OPERATIONS → resolve { NO_ACTION }           200 ✅
resolve مرتين                                409 COMPLAINT_ALREADY_RESOLVED ✅
رد فاضي بلا صورة                              422 COMPLAINT_MESSAGE_EMPTY ✅
شكوى تانية على نفس الحجز                      409 + meta.complaintId + reference ✅
وصف أقل من ٢٠ حرف                             422 ✅
```

**والأهم:** كتبنا ملاحظة داخلية (`isInternal=true`) من حساب أدمن، وروحنا
شفنا `/me/complaints/:id` من حساب صاحب الشكوى — **مش موجودة**. ✅

الإشعارات مطابقة للوصف بالكامل: `unreadOnly`، `unreadCount` مع كل رد،
`PUT` (والـ `POST` بيرجع 404)، التعليم مرتين ٢٠٠، والـ deep link بتاع
`complaint` شغّال.

## سادسًا: بند إطلاق مش تقني

**نظام المحتوى اتشحن وفاضي.** `/admin/cms/pages` و`/public/pages` الاتنين
بيرجّعوا `{ items: [] }`.

يعني **الشروط والأحكام** — وهي وثيقة نظامية — بتتعرض من نسخة مضمّنة جوّه
التطبيق، ومحدش يقدر يعدّلها من غير إصدار جديد للواجهة.

الربط جاهز من ناحيتنا وبيشتغل أول ما تتحط أول صفحة. محتاج حد يكتب المحتوى.
